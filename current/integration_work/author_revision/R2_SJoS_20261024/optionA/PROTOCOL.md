# Option A: matched-resolution M5 comparison, frozen protocol

Written and hashed before any SIIE fit with 8 slices was run on an M5 sample
(see `FROZEN_SHA256.txt` and `EXECUTION_RECORD.md` for the actual chronology).

## Status of this study

This is a follow-up chosen by the author on 24 October 2026 (Taipei time) after
earlier evidence: M5 was featured in R1 under a performance-based inclusion rule,
and the R2 reviews asked whether its gain over SIIE with 4 slices persists at the
same response resolution. It reuses the existing R1 confirmatory M5 samples. It
is not an independent confirmation of the decision to feature M5, and it is not a
retrospectively preregistered experiment. Freezing fixes only the execution,
summaries and the reporting rule below.

## Samples (exactly these; no others)

The C1 rows of `R1/candidates/design_seeds_confirm.csv`: 200 replications,
replication r has seed 9210000 + r (9210001 to 9210200). Model M5 (`gen_M5`):
X ~ N_p(0, Sigma), Sigma_ij = 0.5^|i-j|, Y = 2(b1'X)^2 + exp(b2'X) e, with
b1 = (1, 2, 0, ..., 0, 2)'/3 and b2 = (0, 0, 3, 4, 0, ..., 0)'/5; d = 2,
n = 400, p = 10, alpha = .20, c = 0. Each sample is regenerated by
`set.seed(seed); gen_model("M5", 400, 10, c = 0)`, as in `one_rep_v8()`.
Before any fit, the runner checks that the ledger has exactly these 200 rows and
constants and that the archived `records_confirm.rds` C1 rows use the same seeds.
Exploration (911xxxx) and sensitivity (93xxxxx) samples are not used.

## Code version

Sources loaded exactly as in the R1 confirmatory run: the primary estimator
script through `integration_work/simulation/lib_sim.R` (`DSIIE_SIM_SRC`),
`integration_work/simulation/methods_corrected.R` and
`integration_work/author_revision/methods_v8.R`. Their MD5 values must equal the
`source_md5` attribute of `records_confirm.rds` (primary ef880bd1...,
corrected 44416bed..., v8 5b914c84...); otherwise the runner stops. R 4.6.1.

## Configurations per sample

1. SIIE (4 slices): `siie_q(X, Y, 2, 4, .20)`.
2. SIIE (8 slices): `siie_q(X, Y, 2, 8, .20)`.
3. DSIIE (4 primary slices, 2 fine cells each): `dsiie(X, Y, 2, 4, 2, .20)`.

`siie_q(X, Y, d, S, a)` is `dsiie(X, Y, d, H = S, K = 1, a)`. SIIE at two slice
counts is one estimator; the eight-method benchmark is unchanged. Each fit is
wrapped in `safe_fit`.

## Identity checks (per replication)

A. Archive reuse: the regenerated SIIE (4 slices) and DSIIE r_ave and r_min must
   agree with the archived C1 confirmatory values to at most 1e-10 (exact
   agreement expected because code, seeds and platform are unchanged). Any
   discrepancy is recorded and investigated; the archived values are never
   overwritten, and the comparison table then reports the regenerated values with
   the discrepancy disclosed.
B. Matched fine objects between SIIE (8 slices) and DSIIE, slice j = (h-1)K + k:
   (i) memberships: for each cell, the set of observation indices recomputed from
   `order(Y)` and `rank_split(n, 8)`, and its Y range (minimum, maximum), used to
   check that both fits' centres equal colMeans of the whitened rows of that set;
   (ii) counts n_j = n_hk; (iii) weights omega_j (SIIE) and omega_h q_{k|h}
   (DSIIE); (iv) centres c_j and c_hk; (v) scatters Omega_j and Omega_hk;
   (vi) whitening matrix Sigma^{-1/2} (divisor n). Counts must be equal exactly;
   the remaining maximum absolute differences must be at most 1e-12 (the
   computations are the same floating-point operations, so exact zero is
   expected; 1e-12 allows only for summation-order differences in the weights).

## Metrics and summaries

r_ave and r_min (d = 2) for each configuration, as in `one_rep_v8()`. For each
configuration: number of successful fits, failures, mean and Monte Carlo
standard error sd/sqrt(R_ok). Paired differences over replications in which both
fits succeed: DSIIE - SIIE (4 slices), DSIIE - SIIE (8 slices) and, for context,
SIIE (8 slices) - SIIE (4 slices), for both metrics: mean, 95% Monte Carlo
half-width 1.96 sd/sqrt(R_pairs) with sd the usual (R_pairs - 1)-denominator
standard deviation, R_pairs, and the number of replications in which the first
configuration is larger. Three decimals in the article.

## Failure handling

A failed fit is recorded with its message, counted and reported, and excluded
only from the means and pairs it belongs to. No retry, no replacement seed, no
imputed value.

## Reporting rule (fixed now)

All three configurations, both metrics and all paired contrasts are reported
whatever the outcome, together with failures and the identity checks. For each
metric, DSIIE - SIIE (8 slices) is called a gain at matched resolution if its
95% interval lies entirely above zero, a loss if entirely below zero, and no
detectable difference otherwise. The article states whether the M5 gain over
SIIE (4 slices) persists against SIIE (8 slices) on these samples. A result for
SIIE configurations says nothing about the other six methods.
